# Synthetic Data for the CanRisk Agent Experiments

**Core idea:** one structured **Vignette** is the seed. Every experiment's
input and expected output derives from it — and expected outputs are never
hand-computed. They come from either (a) the **real API** (risk numbers) or
(b) **construction** (known injected error → known flag; known profile → known
extraction).

## Authoring pipeline (seeds → realistic → scale)

Following the agreed design:

1. **Real seeds** (`seeds_real.py`) — a few pedigrees encoded from public case
   reports / NCI reference pedigrees, each **cited**. Pedigree facts aren't
   copyrightable; ages the source doesn't give are filled plausibly and marked
   `(inferred)`. This is the realistic backbone.
2. **AI-refined variants** (`generate_v2.variants_from_seed`) — each real seed
   spawns diversified variants (demographics jittered, affected-structure kept),
   so realism is *inherited from real families* rather than invented.
3. **Synthetic grid** (`generate_v2.sample_synthetic`) — fully-sampled cases over
   two independent axes:
   - **difficulty** = family-structure complexity (easy/moderate/hard)
   - **extremity** = how typical the values are (normal/medium/extreme)

## Two rules the pipeline enforces

- **Extreme ≠ implausible.** Extreme cases sit at the *edge* of the valid range
  but stay inside plausibility bounds → they produce valid risk outputs and
  never trip the agent's gate. `assert_valid()` proves the whole main bank has
  **0 hard plausibility flags**. Implausible cases live ONLY in the Exp-2
  perturbation set (`perturbations.py`).
- **Broad diversity, reported not quota'd.** Wide draws over ethnicity, PRS
  ancestry, Ashkenazi status, family structure, genes, and cancer types;
  `coverage_report()` shows what landed (no hard targets, per the agreed approach).

## The three derivation layers (unchanged, cheapest first)

1. **Sample** — parametric, reproducible given a seed. No keys.
2. **Oracle** (`fetch_gold_output`) — real API → gold risk output. Needs `CANRISK_*`.
3. **Render** (`render_conversation_prompt`) — LLM → conversation, with a `style`
   knob (the Exp-4 conditions). Needs an LLM key.

## Data → experiment map

| Experiment | Input | Expected output | Generated by | Scaling |
|---|---|---|---|---|
| **1 Equivalence** | vignette conversation | gold risk result | render + oracle | N × 1 |
| **2 Safety net** | perturbed vignette | flag verdict (by construction) | `build_exp2_dataset` | N × 6, no keys |
| **3 Efficiency** | vignette persona | metrics + accuracy (vs Exp-1) | render as persona | subset × users |
| **4 Extraction** | conversation in a style | ground-truth fields | render × 6 styles | N × 6 |
| **5 Reliability** | vignette, repeated ×models | gold result; measure variance | oracle + reruns | subset × K × models |

## Files

- `vignette_schema.py` — Vignette / FamilyMember / RiskFactors; CanRisk 2.0 +
  JSON serialization; variable family; now carries extremity, ethnicity,
  ancestry, source.
- `seeds_real.py` — cited real-derived seeds (BRCA1 young-onset breast; HBOC
  ovarian sibship; BRCA2 archetype).
- `generate_v2.py` — seed-variants + difficulty×extremity synthetic grid,
  `assert_valid()` (plausibility invariant), `coverage_report()` (diversity).
- `generate_vignettes.py` — the original layer-1/2/3 functions (oracle + render
  interfaces) reused by v2.
- `perturbations.py` — Exp-2 error library (implausible values live only here).
- `vignette_bank_v2.json` — a saved example bank.

## Tested (no keys)

Real-seed encoding + CanRisk serialization for every vignette, the two-axis
grid, the **0-hard-flag validity invariant**, JSON round-trip, diversity
coverage, and the 6× perturbation expansion. Oracle and LLM-render are wired and
ready once `CANRISK_*` and an LLM key are available.

## Coverage gap to flag to the mentor

The schema models family history fully, but the **agent** currently ingests only
Personal + Lifestyle, so fully-meaningful end-to-end runs of Experiments 1/3/5
wait on the Pedigree section. Until then those run on the personal/lifestyle
subset with a placeholder family — real but partial. The data is already
complete, so nothing needs regenerating when pedigree lands.
